# 電性核心 Phase 0–1 實作清單

2026-09-13；依使用者確認的 `wiring-panel-electrical-plan-v0.1.md`，從 WIRE-R5 開始。

本次交付可追溯電性表、教學配置與單輪純 TypeScript 求解。自保持迭代、馬達三相判斷、UI 送電與動畫屬後續 Phase 2–4。

## 約束

- 穩定端點 ID、既有幾何與路由不變。核心不匯入 Three.js、DOM 或元件演示狀態。
- 規格未證實時明列教學假設；MC1 側翼未辨識端子不猜橋接。
- 理想導線與閉合接點合併成 net；線圈、燈與蜂鳴器不能合併。
- 來源兩端與 profile 明確設定，不把 QF 或 A2 當作隱含電源或中性線。
- 錯誤端點、參與接線的缺漏規格、短路、来源衝突及串聯負載均有診斷；輸入不變。
- 依既有 Site 所有權規則，由主代理編輯現有 checkout 的 feature branch；研究與唯讀審查可獨立進行。提交／同步依 AGENTS.md 的既有授權執行。

## Task 1：電性規格與測試契約

建立 `docs/electrical-models.md`、`src/electrical/contracts.ts`、`catalog.ts` 與 `qa/electrical-check.mjs`。測試先失敗，再補實作。明確列出按鈕、急停、選擇、QF、FU、TB、MC1、AP1、TH1、空插座與未支援型號。教學電源提供 L/N 兩端；教學馬達保留 U/V/W 端點並明列 Phase 2 尚未支援。

驗證真值表、端子 ID 對照、同格橋接／鄰格隔離、演示狀態不介入、未知端子阻擋與未接線模型不阻擋。

## Task 2：網路與單輪求解

建立 `netlist.ts`、`solver.ts`，必要時將圖路徑演算法獨立。輸出排序穩定的 net、導通證據、接點狀態、負載結果及原因代碼。只更新計算結果，不修改輸入或既有元件。

驗證來源→按鈕→線圈→回路；斷線、兩端同電位、來源關閉、極性互換、短路、來源衝突、profile 不相符、串聯負載與懸空支路。驗證元件／電線順序、反向端點與幾何中繼資料無關。回授狀態為明確參數，單輪不偷偷鎖存或迭代。

## Task 3：整合與交付

將電性測試加入 `npm test`，補一項與實際模型端子集合的整合檢查。更新 ARCHITECTURE；執行完整測試與建置，進行獨立唯讀程式碼審查。核對 GitHub 最新 main，提交並驗證同一 source tree，同步既有 Site。UI 尚未匯入新核心，因此 WIRE-R5 畫面行為不變；不宣稱完成瀏覽器通電操作驗收。
