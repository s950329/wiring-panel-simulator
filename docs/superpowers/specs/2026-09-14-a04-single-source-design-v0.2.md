**已確認的供電原則：目前這個配線盤只有一組外接電源、一顆盤上總開關。按 A04 正確接線後，總開關後方的馬達回路、控制回路、指示燈與蜂鳴器都使用同一組電，沒有獨立 CONTROL 供電。** [U1]

「主迴路」與「控制迴路」只是電的用途不同，不代表兩個來源。程式中的相間供電能力，只用來判斷同一電源的 R–T 能否供控制負載使用，不代表新增設備。

文中的「現況」來自原圖、使用者匯出檔與上述程式基準；新增欄位、規格 ID、行為及驗收均為提案。本文不宣稱新格式或 API 已可使用。

### 先看正常使用方式

按 A04 完成進線及盤內配線後，在測試模式下：**QF1 ON → 下游回路可以取電；QF1 OFF → 下游回路失電。** 馬達仍須由 ON／OFF 按鈕及接點決定是否啟動，不是扳總開關就直接運轉。

這裡的「下游失電」以正確按 A04 接線為前提。電源進線端不因 QF1 OFF 而變成無電；若故意接線繞過 QF1，求解器必須呈現實際旁路結果，而不是硬把全盤判定斷電。

本版先修訂規格；「單一電源、單一總開關」不再列為選項讓使用者重複確認。介面與舊檔處理的具體方案仍由本文審閱。

## 1. 問題與目標

### 1.1 已確認的差異

A04 原圖標示 `3Ø AC220V`。控制支路在 NFB1 之後，由 R 相經第一個 FUSE 進入控制回路，另一端經第二個 FUSE 回到 T 相；圖中沒有把這個返回端畫成 N。[S0]

前一份 A04 交付方案改用獨立 `CONTROL:L/N` 接到 FU1 的兩個 IN。R12 將這種連接保存為外接線，參與電氣運算，但不是盤內具有 3D 路徑的黃色線。因此「模擬可以啟動」不等於「接線忠實呈現原圖」。本次須同時修正來源語義與接線資料，而非只補兩條裝飾線。[S3]

現有 `ThreePhaseSource` 沒有相間兩端負載能力；`solver.ts` 的一般負載供電判斷只使用二端來源。`power.ts` 會將不同啟用來源共用理想導通網路判成 `SOURCE_CONFLICT`。保留獨立 CONTROL，再補上 MAIN→FUSE，不是正確修法。[S4–S6]

### 1.2 本次成功的定義

1. 兩個 FUSE 的 IN／OUT 共四個端子，都有正確的盤內接線。
2. 啟動、保持、停止與警報由實際端子連通及 MAIN 相間供電決定，不依賴隱藏 CONTROL。
3. QF1 斷開或主電源失效時，A04 控制回路與馬達均失去供電。
4. 接線畫面、保存的端點及電氣證據一致；本盤的正常操作與一般匯入均不能重新引入獨立 CONTROL。舊錯誤檔案保留原檔，不以「相容」為由繼續啟用雙電源。

## 4. 架構選擇

| 方案 | 評估 |
|---|---|
| 保留 CONTROL，補畫 MAIN→FUSE | 畫面與求解拓樸分裂；若真的連入，又造成獨立來源衝突。不採用。 |
| 同一三相來源明示可用相對 | 採用。保留既有導通模型、來源衝突檢查與馬達判斷，只增加可供一般負載使用的相對。 |
| 改為完整交流數值求解器 | 能力遠超本次需求，也需補齊設備額定資料與新驗證基準。本輪不採用。 |

責任邊界如下：

- **內建電源規格**：定義端子、三相 profile、可用相對與其負載 profile。
- **專案配置**：選用哪個電源實例及其持續設定，不內嵌求解程式。
- **connections**：表示哪些端子真的連接，不新增隱藏分支。
- **電性引擎**：由同一輪 netlist 判斷實際來源與供電。
- **路由與畫面**：盤內連接使用共同接線服務；來源卡片及電性說明忠實反映配置與結果。

`MAIN`、`QF1`、`FU1`、`MC1` 僅為 A04 實例名稱。能力辨識與求解不得依賴這些固定 ID。

**單一來源限制放在本盤的配置驗證與 application 層，不刪除純電性核心辨識多來源錯接的能力。** 原有二端來源／混源負向測試仍可在測試程式中使用；這不等於網站仍提供第二組供電。

完成的本盤練習只配置一個來源。未接進線或未放入來源的編線草稿可以保存，但須呈現「未接入電源」，不得由程式自動補 CONTROL 或其他來源來讓它運轉。

## 5. 資料契約

### 5.1 引擎輸入：擴充 ThreePhaseSource

在現有 `ThreePhaseSource` 增加可選 `lineToLine` 陣列；原有 `id`、`phases`、`profile`、`enabled` 保留。

| 欄位 | 規則 |
|---|---|
| `lineToLine` | 可省略或為空；代表沒有宣告任何相間兩端負載能力。每個來源最多三項。 |
| `lineToLine[].phaseIndices` | 二個不同整數，取自來源 `phases` 的索引 0、1、2，採 `i < j` 的標準順序。 |
| `lineToLine[].profile` | 非空相容性識別；由內建規格生成，與一般負載 profile 比對。 |
| 每個相對 | 最多一項，不能重複宣告或用不同 profile 重複占用。 |
| 啟用條件 | 完全繼承該來源的 `enabled`；不另設相對 enabled 或全域控制 gate。 |

以下是**引擎契約示例**，不是完整專案 JSON，也不能直接匯入 R12：

```json
{
  "id": "MAIN-SUPPLY",
  "phases": [
    { "component": "MAIN", "terminal": "L1" },
    { "component": "MAIN", "terminal": "L2" },
    { "component": "MAIN", "terminal": "L3" }
  ],
  "profile": "teaching-three-phase-v1",
  "enabled": false,
  "lineToLine": [
    { "phaseIndices": [0, 1], "profile": "teaching-control-v1" },
    { "phaseIndices": [0, 2], "profile": "teaching-control-v1" },
    { "phaseIndices": [1, 2], "profile": "teaching-control-v1" }
  ]
}
```

`enabled: false` 在此例表示模擬尚未執行，不表示 QF1 已拔除進線，也不表示刪除來源能力。即使來源未啟用，無效索引、重複相對及錯誤資料仍須驗證並拒絕。

此例的三組相對來自明確選用的 AC220V 教學電源規格；不得自動套用到所有三相來源。A04 題圖驗收仍要求實際取 R–T；接成 R–S 即使模型允許供電，也不算忠實重現 A04。

### 5.2 內建規格與專案配置

提議新增內建來源規格 `teaching-ac220-three-phase-source`，`definitionVersion: 1`，表示本盤唯一的外接三相來源及其相間教學能力，不表示再新增一顆實體電源。名稱及欄位為提案，尚不是現站 API。

舊通用三相電性定義在核心測試中可維持原行為；本盤的新 A04 配置明示選用支援相間能力的規格。日常 JSON 只引用內建規格，不內嵌電源模型或任意新增能力。[S2]

下列僅為 `configuration.components` 的單一實例片段：

```json
{
  "id": "MAIN",
  "definitionId": "teaching-ac220-three-phase-source",
  "definitionVersion": 1,
  "placement": null
}
```

**刪除 v0.1 的 `state.available` 設定。** 本盤不另存供主迴路或控制迴路切換的軟體電源勾選。三條 MAIN→QF1 端子接線代表進線是否完整；沒有進線就不能供應盤內負載。

內部 `ThreePhaseSource.enabled` 保留作為求解契約：正常本盤 runtime 中由「是否在測試模式執行模擬」導出，不讀取另外的 control／main 勾選，也**不依 QF1 ON／OFF 決定**。QF1 開關的效果必須由其三組實際接點反映。停止模擬是結束運算，不等於把實體電源拔掉。

完成的新 A04 在引擎層應產生 `sources: []` 與一項 `threePhaseSources`；不得生成 CONTROL 設備、CONTROL-SUPPLY 或另一個相間 Source。來源數量按電性能力計算，不靠名稱比對，因此把 CONTROL 改名也不能繞過單一來源限制。

零來源草稿可載入並保持未送電；兩個以上來源、獨立二端來源或無法映射到本盤供電方式的來源配置，屬本盤不相容配置。驗證失敗不得提交到現用盤面。

### 5.3 派生資料

供電相對候選只在求解期間建立，含原來源 ID、兩個來源端點／網路、相對索引與 profile。它不是新的 `Source`，不增加第四組電源，也不加入導通網路。

`LoadResult.sourceIds` 繼續回報原始來源 ID；相間供電時只有 MAIN 所屬的來源 ID，不回報虛構 CONTROL。提議增加可選 `supplyEvidence`，保存 `kind: line-to-line`、`sourceId`、`phaseIndices`，供說明層使用。舊二端供電結果可以不帶此欄位；派生證據不作持續狀態匯入。

## 6. 求解規則

### 6.1 不可破壞的原則

只有使用者接線、已宣告固定連接及當下閉合接點，能合併成理想導通網路。線圈、燈、蜂鳴器、馬達與來源相對都不是導線；不能為了判定供電而把 R 與 T 合併。[S5、S8]

### 6.2 判定次序

1. 驗證元件、端點、輸入、來源及相對宣告；沿用既有無效資料診斷。
2. 依這一輪接點／線圈狀態建立 netlist。QF1、兩個保險絲、按鈕及 TH 接點都參與實際導通。
3. 先以**原始來源清單**檢查短路與跨來源衝突，再建立相對候選。
4. 一般負載兩端為同網路時判定 `unpowered / same-potential`。
5. 找出兩端網路吻合的供電候選：原有二端來源，或同一個啟用三相來源已宣告的兩個不同相別。兩端對調不改變結果。
6. 候選 profile 與負載相容才判定 energized；不相容維持 `INCOMPATIBLE_SUPPLY`，不假設「接到兩相就能用」。
7. 沒有直接供電候選時，沿用負載路徑分析，區分開路、串聯負載與未支援的來源網路；不依負載可達性把懸空分支誤判成閉合回路。
8. 交回既有穩態回授流程，同時更新線圈，收斂後才發布畫面與證據。既有迭代上限、震盪及 halted 行為不放寬。

系列路徑分析的可供電端對增加已宣告相對；完整來源網路診斷仍保留未宣告三相端對的辨識。兩者不能混為「所有端對皆可供電」。

### 6.3 故障與相容行為

| 情境 | 必要結果 |
|---|---|
| 同來源、不同相、已宣告且 profile 相容 | 一般負載可供電，來源仍只有一個。 |
| 同一相接到負載兩端 | 不供電；不是相間電壓來源。 |
| 接到未宣告的相對 | 維持原有不支援診斷，不自動放行。 |
| 同一啟用來源的不同相直接短接 | `SOURCE_SHORT`；不得發布中途亮燈／吸合結果。 |
| 兩個不同啟用來源共用理想導通網路 | 保留 `SOURCE_CONFLICT`，不以同電壓標示豁免。 |
| 不同來源透過負載連成閉合網路 | 依既有分析回報不支援，不能當成單一相間供電。 |
| 跨來源但沒有閉合回路的懸空分支 | 不因新增相對而誤報成可供電或一律短路；保留原有分類。 |
| 相間負載串聯 | 不新增數值分壓能力，保留 `UNSUPPORTED_SERIES`。 |
| 缺少回線／保險絲不導通 | 控制支路開路，不能吸合。 |

### 6.4 馬達判斷

馬達仍只認原始三相來源的三個不同相別，仍檢查缺相、重複相別、混源及相容 profile；相對候選不得進入馬達來源索引。[S5]

**MC1 吸合或 GL 綠燈亮不代表馬達一定得到三相。** 例如 S 相供電線缺失但 R–T 控制支路完整，MC1 與綠燈可以保持，馬達應顯示未供電／缺相。新增驗收必須區分這兩件事。

### 6.5 總開關必須是接點，不是全域停電捷徑

外接電源接至 QF1 進線 L1／L2／L3；QF1 的狀態決定 L1–T1、L2–T2、L3–T3 三組接點是否導通。扳掉 QF1 不移除 MAIN、不把全部 sources 設為 disabled，也不直接把所有負載輸出清零。

按 A04 正確配線時，主迴路與控制支路都在 QF1 的出線端，所以 QF1 OFF 後一起失去供電；但進線端仍連至外部來源。

若刻意把 FUSE 接到 QF1 的進線側以繞過總開關，求解器仍須照端點判斷，控制負載可能在 QF1 OFF 時取電。這種接線不是合格 A04，但可作錯線案例；不得透過 `if QF1 is off then all loads off` 假造正確結果。A04 範例的忠實度另以端點核對測試保障。

## 7. A04 接線與元件映射

### 7.1 本次接線差異

| 動作 | 端點 |
|---|---|
| 移除 | `CONTROL:L → FU1:F1-IN` |
| 移除 | `CONTROL:N → FU1:F2-IN` |
| 新增盤內連接 | `QF1:T1 → FU1:F1-IN` |
| 新增盤內連接 | `QF1:T3 → FU1:F2-IN` |

A04 專案不包含獨立 CONTROL 設備。三相電源到 QF1 的三條外接線、TH1 到 M1 的三條外接線保留；兩個 FUSE 的 OUT 接回原有控制分支。不得只增加新線而忘記移除兩條 CONTROL 外接線。

以前一版 26 條盤內線、8 條外接線為比對基準，替換後預期為 **28 條盤內線、6 條外接線**；三條 MC1→TH1 固定組裝導體另外計算。這是 A04 範例的核對值，不是通用匯入器的硬編碼規則。[S9]

四個 FUSE 端子都要可追查：F1-IN 來自 QF1:T1，F1-OUT 進控制供電分支；F2-OUT 接控制返回分支，F2-IN 回到 QF1:T3。IN／OUT 與 connections 的 from／to 是端子及資料方向，不能解釋成交流電流永遠單向。

### 7.2 沿用的教學元件

| A04 功能 | 模擬器端點／行為 |
|---|---|
| OFF 停止 | PB5 的 NC：3–4。 |
| ON 啟動 | PB3 的 NO：1–2。 |
| 自保持 | AP1 的 NO：53–54，跟隨 MC1。 |
| MC 線圈 | MC1 A1–A2。 |
| 過載正常切斷回路 | TH1 TC–TB，正常導通、跳脫斷開。 |
| 過載警報 | TH1 TC–TA，跳脫導通；HL3 與 BZ1 警報。 |
| MC 狀態綠燈 | AP1 NO：83–84 控制 HL4。 |

這是已支持教學模型的映射；原圖的 MC1/a 由 AP1 兩組已宣告 NO 實現，不使用仍未確認電性的 MC1 側翼端子。保持元件局部幾何、端子 ID、顏色及既有附件組裝，不以改基準測試掩蓋差異。[S7]

### 7.3 路由

新增的兩條連接必須呼叫手動接線、專案匯入及離線產檔共用的接線服務。不可人工填寫高架 `points`，不可只改 `viaDucts`，不可用外接線繞過盤內幾何驗證。

相同引擎、配置、姿態與順序應得到相同路由結果。線槽優先、端子夾線點、淨空、線距、自交及操作板開闔都須驗證。新線與 QF1 原本主電路分支共用端子時，須分配可用夾線點；不能假設一個端子只能有一條線。

全部接線按完整有序端點清單重建；失敗就指出兩端並保留原專案，不漏線、不降低間距、不另畫盤外假線。路由上下文參數化依關聯專案規格實作，本規格不再定義第二套方案。[S2]

## 8. 操作介面與狀態

### 8.1 本配線盤只有一組外接電源

目前配線盤的預設配置、A04 範例與正常載入流程都不產生獨立 CONTROL，不提供「A04 單電源／其他雙電源」模式切換。

| 項目 | 本版規範 |
|---|---|
| MAIN 進線端子 | 保留 L1／L2／L3 接線入口，可顯示 R／S／T 對應。它是一組三相電源，不是三顆電源。 |
| QF1 總開關 | 唯一的日常供電／斷電操作，盤上模型與其操作面板控制同一個狀態。 |
| 獨立 CONTROL 卡片及 L／N 端子 | 從本盤 runtime、預設配置與介面移除，不只是隱藏 UI。 |
| 「控制電源／主電源」勾選 | 移除；不得在背景保留會分別供電的狀態。 |
| MAIN 狀態說明 | 顯示接線／來源證據，不另提供 available 電源開關。 |
| PB3／PB5 | 分別啟動／停止 MC 控制動作；不是另外兩個來源。 |

題圖說明可標示「控制回路由總開關後 R–T 取電」。實際證據仍取自當輪求解，例如「MC1 線圈由 MAIN 的 L1–L3 供電」，不能無條件顯示已通電。

### 8.2 配線／測試模式不是第二顆供電開關

軟體仍需區分「可以編線」與「執行模擬」；此模式不屬於實體盤的電路元件。

建議將原「送電模擬／停止模擬」操作改為「開始測試／返回配線」，並明示目前為配線模式或測試模式。這是待審的介面文案修正，不增加來源或選擇性供電邏輯。

- 配線模式：允許接線、刪線、匯入；不運行電性求解，也不把未執行標成實測無電。
- 測試模式：執行單一來源的求解、禁止改線；使用者扳 QF1 ON／OFF 決定正常 A04 下游供斷電，不需另外勾主電源或控制電源。
- 返回配線：停止求解，清除線圈記憶及暫態操作，保持已保存的 QF1 持續狀態；介面顯示「模擬未執行」，不是宣稱進線已拔除。

A04 範例預設 QF1 OFF。匯入使用者檔案仍可還原 QF1 ON，但不自動開始模擬；使用者選擇開始測試時，依當下開關及接線求解，不偷偷改成 OFF。ON 啟動鍵已釋放的完整 A04 不會因進入測試就自動吸合。

### 8.3 總開關、啟停與復歸

| 條件／操作 | 按 A04 正確接線的預期 |
|---|---|
| 進線完整、測試中，QF1 OFF | 進線端連至來源，但 QF1 後方負載沒有供電。 |
| QF1 ON，尚未按 ON | 下游可以取電；MC1 未吸合，馬達不運轉。 |
| 按 ON 後放開 | MC1 由自保持回路維持吸合，綠燈亮，馬達供電需另外確認三相完整。 |
| 扳 QF1 OFF | MC1 釋放、馬達失電，綠燈與任何過載警報也一起失去供電。 |
| QF1 再 ON | ON 已放開時不自行重新啟動，需再按 ON。 |
| 運轉中按 OFF | 切斷線圈控制，MC1 釋放；不是把整個配線盤電源拔除。 |

匯入永遠保持模擬未執行，瞬時按鈕釋放、線圈記憶清除。任一 FUSE 控制通路中斷亦不能維持 MC1 吸合；保護蓋開闔不是熔斷狀態。

**「不自啟」的前提是 ON 已放開。** 若持續按住 ON，回復供電／TH 復歸後可依原接點邏輯再次吸合；本輪不加入原圖沒有的防再啟動鎖定。進線故障與故意旁路是另外的錯線條件，不能用全域 QF1 gate 掩蓋。

## 9. 保存、相容與版本

### 9.1 與另一份待審規格銜接

日常格式使用其既定的 `format: wiring-panel-project`、`schemaVersion: 1`、`configuration` 與只含端點的 `connections`。本次只擴充內建來源規格及其電性建構，不新增頂層持續保存的 solver sources、虛擬相對電源或路徑資料。[S2]

保存唯一來源的規格引用、進線端點及 QF1 等器件的持續狀態；不保存額外 control／main／available 供電勾選。派生 enabled、候選相對、電性結果及來源證據均重算。普通匯出不保存動畫姿勢、線圈記憶或執行中的模式。

### 9.2 R8–R12 舊檔：保留資料，不保留錯誤供電

本節修正 v0.1「舊獨立 CONTROL 仍可原樣操作」的方案。它不符合使用者已確認的本盤供電方式，不能為了相容而當成網站第二種正常模式。

舊檔處理先解析配置與端點，再驗證是否能無歧義轉為本盤的單一來源。原始檔永不覆寫，也不以檔名含 A04 作為改線依據。

| 舊資料情況 | 處理方式 |
|---|---|
| 只有無接線的程式自動附加 CONTROL | 確認無使用者／固定連接或其他功能依賴後可在副本移除，明示轉換報告；只有程式自動附加的 CONTROL-SUPPLY 不算使用者引用，不保留為可操作來源。 |
| CONTROL 仍接到 FUSE 或其他端子 | 拒絕自動載入本盤，指出兩端與不相容供電；原盤保留。不能原樣啟用，也不能默默改接至 QF1。 |
| 多個來源、來源身份或設定無法無損映射 | 明確不相容；舊 main／control 勾選不可猜成新的總開關狀態。 |
| 來源可識別且無衝突，但未宣告相間能力 | 不擅自增加能力。可保留為未完成草稿並給出不支援供電診斷；不可標成已修正 A04。 |
| 有效單一來源配置 | 端點、可映射持續狀態與組裝保留，依共同流程重建並保持未執行模擬。 |

對已交付的錯誤 A04，另外生成清楚命名的修正版範例：移除兩條 CONTROL 外接線、加上 QF1→FUSE 盤內線、選用明示相間能力的唯一來源。完整變更清單及原檔保留，不宣稱是無損格式轉換。

本輪不新增舊雙電源執行模式、相容開關或複雜的自動修線精靈。若未來要支援其他實體供電配置，另列需求，不影響本盤單一來源基準。

電性核心仍須保留 `lineToLine` 省略時的舊行為，以及二端來源、短路／混源等測試；這些是核心回歸，不是本盤 UI 的可用模式。[S4–S6]

與關聯專案格式設計第 6 節的銜接：通用解析器可以讀出原資料，但進入本盤之前須再做單一來源配置驗證。若兩份文件對「可執行的舊檔」仍有衝突，實作前同步審閱，不默默沿用 v0.1 的雙來源還原。

### 9.3 發布邊界

目標是下一個含此能力的應用程式修訂，暫稱 WIRE-R13；若其他已核准改動先占用修訂，按實際整合結果順延。應用程式修訂、專案 schemaVersion、內建型號 definitionVersion 是三個不同版本，不相互代替。

電性核心可先獨立開發與測試；完整 A04 專案／UI 交付仍依賴已審閱的來源配置與專案匯入介面。關聯規格未核准或尚未具備時，不另塞一套臨時 R13 snapshot 協定，不宣稱 R12 現站已能匯入新檔。

本輪審閱只產生文件，不部署。未來發布仍使用既有 Site；網站、離線 HTML 與 A04 範例須對應同一組已驗證來源。
