# 配線專案檔與動態盤面重建 — 設計 v1.0

日期：2026-09-14  
狀態：核心方向與元件庫邊界已確認；本文件待審閱，尚未實作。  
程式基準：`s950329/wiring-panel-simulator`，commit `2dd81b73b946be25dd0afa515dd4ba4532afa160`（應用程式 WIRE-R12）。

## 1. 目標與範圍

保存的單位改為「配線專案」，不再是固定 BOARD 024 的畫面快照。

**檔案保存使用者決定的配置、參數、持續操作狀態及端子連接；程式重建元件、電路與導線路徑。** 元件擺放座標是必要配置，電線路徑座標則不是。

已確認：單一 JSON 內分為 `configuration` 與 `connections`；匯入等於重建整個專案；元件與盤面解耦；第一版只組合程式內建元件庫的型號。BOARD 024 成為預設專案資料，不再是匯入白名單。

本次不做拖拉配置編輯器、任意 3D 造型、JSON 內嵌元件程式、執行任意腳本、遠端下載型號、真實電流／轉速／保護時間計算，也不恢復正在執行的模擬。新增型號仍經過元件庫、模型與測試流程。

第一版沿用現有矩形底板與可翻轉操作板的建模能力：一塊底板、零或一塊操作板，可配置尺寸、位置、線槽、導軌與元件。盤內平面擺放與線槽方向支援 90° 的整數倍；相機環繞不受此限制。任意斜向安裝、多層箱體及其他鉸鏈機構不列入本輪驗收。

## 2. 設計選擇

| 方案 | 結論 |
|---|---|
| 固定盤面＋端點接線 | 太依賴預設盤面，無法保存不同元件組合及擺放位置，不採用。 |
| 專案配置＋端點接線 | 採用。可重建使用者配置，走線仍完全由程式負責。 |
| 完整執行快照 | 保留供除錯，不作一般專案檔；不要求使用者維護材質、端子座標及求解結果。 |

元件庫定義「某型號是什麼」，專案配置定義「使用哪些實例及如何安裝」，連線資料定義「實例的哪些端子相連」。元件型號不得依賴 `MC1`、`PB3` 或 BOARD 024 等特定實例名稱。

檔案可攜性以「匯入端具備相容的內建型號版本」為前提，不宣稱 JSON 可獨立攜帶任意新型號。

## 3. 專案格式

### 3.1 頂層契約

| 欄位 | 規則 |
|---|---|
| `format` | 固定 `wiring-panel-project`；與舊 `wiring-panel-snapshot` 分流。 |
| `schemaVersion` | 新格式從整數 `1` 開始；不是 WIRE-R12 等應用程式修訂。 |
| `name` | 可選專案名稱；不參與相容性判斷。 |
| `configuration` | 盤體、安裝結構、元件實例、組裝關係、參數與持續狀態。 |
| `connections` | 有序陣列；每項只有 `from` 與 `to`，各為 `{component, terminal}`。 |

一般專案不保存 `revision`、匯出時間、相機、材質、mesh、端子座標、`points`、`viaDucts`、求解結果、選中狀態、復原歷史或未完成接線。

`from`／`to` 是接線端點，不代表交流電流方向。A→B 與 B→A 視為重複；自接及與固定組裝導體完全重複的連接拒絕匯入。允許多條不同連接共用端子，不能把分支誤判為重複。

線號在執行時產生。陣列次序作為重建順序，匯出不依畫面排序重排；不承諾保留先前刪線後留下的 W／E 編號空缺。

### 3.2 配置與座標

`configuration` 含以下資料；各集合使用穩定 ID，不使用陣列索引作引用。

| 區塊 | 內容 |
|---|---|
| `units` | 固定 `position: scene-units`、`rotation: degrees`；現有比例座標不可改稱實測毫米。 |
| `board` | 底板 `id`、`width`、`depth`、`thickness`。 |
| `operationPanel` | 可為 `null`；否則記錄 ID、內建結構規格及版本、相對底板的鉸鏈位置／方向、尺寸、`state.open`。 |
| `rails`、`ducts` | ID、相對安裝面的 `mountId`、位置、平面旋轉及長寬等建模參數。 |
| `components` | 所有盤內元件與外接設備實例；不得另有程式強制補入的 CONTROL／MAIN／M1。 |
| `assemblies` | 內建組裝規格引用，及其宿主元件 ID。 |
| `panelGateway` | 可為 `null`；有跨操作板配線時指定操作板 ID、過門端子台 ID、盤側／操作板側端子組。 |

底板上表面為 Y=0，X 向右、Z 向前；程式為顯示而居中整個場景，不改寫檔案座標。`position` 均為 `[x,y,z]`，`rotationY` 是安裝座標系中的 Y 軸旋轉。

操作板的鉸鏈與開闔位移由其內建結構規格解釋；板上元件位置相對操作板的固定座標系，不隨當下開闔重寫。線槽與導軌在第一版安裝於底板。尺寸必須是有限正值，角度與安裝位置須在實作白名單及合理上限內；不因檔案帶了數值就無條件建模。

### 3.3 元件實例

每個實例包含 `id`、`definitionId`、`definitionVersion`、`placement`，以及可選的 `parameters`、`state`。

- 自由安裝：`placement` 使用 `{mountId, position, rotationY}`，指向底板或操作板。安裝面是否適用由元件定義驗證。
- 組裝附掛：`placement` 使用 `{assemblyId, slot}`，插槽決定相對宿主的位置與方向，不再另外保存自由座標。
- 外接設備：`placement: null`；只有支援外接呈現的內建定義可使用此值。電源、馬達卡片由專案設備清單產生。

ID 在結構、元件與組裝物件的引用範圍中不可重複；缺少宿主、循環引用、不相容插槽或重複占用插槽均為配置錯誤。同型號可建立多個實例，各自擁有狀態。

元件庫提供端子定義、局部幾何、電性、允許參數、狀態序列化及預設值。匯出只保存規格允許的輸入，不複製說明文字、`group`、`displayName` 或世界變換。

`definitionVersion` 使用明確的相容契約版本。文字、材質及不改變介面的修正，不因此強制改版；端子識別、電性或安裝契約的破壞性變更才升版。未知型號或未知契約版本明確拒絕，不自動換成相似型號。缺少參數／狀態使用該版本的預設值；無效值拒絕，不靜默截斷。

已能顯示外觀但尚缺電性模型的元件，不因本次重構變成可通電：允許保存其已支援的配置，送電時仍依現有電性能力給出不支援診斷，不推測接點。

### 3.4 組裝不是隱藏配線

新增程式內建組裝規格，明確描述可接受的宿主型號、插槽、附掛局部姿勢、機械連動與固定導電連接。第一版涵蓋現有 S-P16 與 AP-22／TH20 組裝。

例如 `assemblies` 的一項引用 S-P16 附件組裝規格與宿主 `MC1`，AP1 的 `placement` 指向該組裝的輔助接點插槽，TH1 指向過載插槽。只有實際存在的附件才產生對應連動或固定導電片。

AP1 隨宿主吸合，不代表其端子與宿主外部端子自動導通；TH1 的三條固定導電片由組裝規格明示。自由擺放在 MC1 旁邊不會自動生成這些連接。固定連接不重複放入 `connections`，但仍可在電路證據中查閱。

## 4. 狀態與送電邊界

| 資料 | 保存及匯入行為 |
|---|---|
| 斷路器 ON／OFF、選擇開關檔位 | 保存並還原。 |
| 急停鎖定、過載跳脫 | 保存並還原，用於故障練習。 |
| 過載電流設定等 | 放在 `parameters`，按型號範圍驗證。 |
| 外接電源可用選項 | 存在該電源實例的設定中；不是全域固定 CONTROL／MAIN 開關。 |
| 操作板及保險絲保護蓋開闔 | 保存語義狀態，不保存動畫中途角度。 |
| 瞬時按鈕、手動壓合／發聲／亮燈演示 | 不還原持續操作；匯入正規化為釋放／結束演示。 |
| 線圈吸合、燈亮、蜂鳴器響、馬達供電及線圈記憶 | 不保存為輸入；清除後由新一輪模擬計算。 |

所有匯入完成後均為未送電；QF1 可以還原為 ON，但必須由使用者按送電模擬。匯出時不改變目前操作狀態，僅對輸出的資料副本排除暫態。相機與選取不進專案檔，成功載入後重新適配視角並清空舊選取。

匯入保存的是可重建的練習設定，不是繼續播放上次模擬。按住啟動鍵、帶自保持記憶或尚未完成的動畫皆不作執行快照恢復。

## 5. 匯入、走線及失敗處理

### 5.1 先建立，成功後替換

先確認目前模擬停止，並等待或取消尚未完成的接線。讀檔後驗證完整配置、引用、參數及端點，在獨立暫存專案建立幾何與電性結構；此階段不清空原專案。

暫存專案套用持續狀態、清除暫態，逐條產生連接。全部完成及目標操作板姿態驗證成功後，單次切換目前的 project session，刷新設備選單與端子 UI。最後清理舊專案的事件、音訊及專屬 GPU 資源；共用元件庫資源按所有權管理，不隨某次替換誤刪。

匯入期間鎖定送電、接線及配置變更，提供進度與取消。取消、任何解析／建模／走線失敗或提交前 session 已改變時，丟棄暫存專案，保留舊專案的配置、接線與狀態；過期非同步結果不能覆蓋新專案。

### 5.2 共用走線規則

手動接線、匯入重建與離線工具使用同一個接線服務，且接收當前專案的線槽、碰撞物及過門規則，不直接匯入固定 `layout.ts`。

盤內線優先進入適合的線槽，再沿依幾何建立的線槽可達關係走線；不再把某個固定索引當作主幹。跨線槽連接必須通過相同淨空／線距檢查，無可行路徑就明確失敗，不退回盤外高架假線。零線槽配置可保存；需要盤內線槽路由的連接在沒有可用線槽時回報配置不足，不偷偷換規則。

操作板側直接接線仍遵守該專案的過門端子側限制。關閉操作板的導線出口由結構規格與尺寸計算，不硬編碼原盤的鉸鏈座標或後緣距離。

有操作板時，在暫存模型使用其已定義的完全展開姿態依序接線，再按檔案的 `state.open` 驗證／重算到目標姿態；對使用者只呈現最後狀態。關閉驗證失敗就整次匯入失敗，不強迫把專案改存為展開。

第一版按 `connections` 陣列順序重建，不新增保存路徑、任意調換順序或全域多線最佳化。相同規格、引擎版本與資料使用確定性次序；不同引擎版本不保證線形相同。端子連接保持一致才是往返保存的主要判準，幾何仍須通過碰撞檢查。

盤內／外接連接由設備能力判定，不由元件 ID 前綴猜測。只有盤內線生成 3D 路徑；外接線參與電路，無須虛構盤內座標。固定組裝導體由組裝規格生成。

### 5.3 驗證不等於電路必須正確

第一版限制：檔案 10 MB、元件 128 個、端子總數 8,192、使用者連接 512 條、線槽／導軌各 64 個、引用深度 16 層；ID 長度 100、名稱長度 200 個字元，座標每軸絕對值不超過 10,000，尺寸為不超過 10,000 的有限正值。搜尋另設有限節點／重試上限與取消檢查，不保證所有上限內配置皆可走線。這些是新格式的資源限制，不是實際電氣額定值。僅採白名單資料；拒絕腳本、未知規格及原型污染欄位，不執行或信任檔案攜帶的模型。

錯誤含資料欄位路徑或連接序號與兩端，如「第 12 條：PB3:2 → MC1:A1 找不到可行路徑」。不得漏線、忽略不認識的元件、靜默改接端子或降低線距來讓匯入成功。

可保存有意的錯線練習；短路、開路、混源、尚缺電性等依現有電性診斷在檢查／送電階段回報，不為了讓模擬正常而修改輸入電路。未知端子、無效實例與無法建立幾何則屬匯入錯誤。

## 6. 舊檔相容與介面

一般按鈕改為「匯出專案 JSON／匯入專案 JSON」，新增或重設專案仍可載入 BOARD 024 預設資料。不新增另一套讓使用者挑選的日常格式；完整快照移至除錯用途。

舊 R8–R12 整盤 snapshot 以轉換器處理：讀取可識別的型號引用、實例配置、狀態、組裝與實體／外接連接端點，正規化為新專案再走相同重建流程。舊 `points`、材質、相機及求解結果不參與一般載入；告知「舊快照已轉換，導線將重新計算」。

轉換不先呼叫要求 metadata 完全相等或驗證舊路徑的還原器，否則會保留舊格式耦合。也不忽略舊配置的矛盾：元件配置、附掛關係或固定組裝連接若無法唯一映射，明確拒絕並指出問題。舊檔聲稱的額外固定接線不得直接執行或靜默遺失。

舊單元件檢視快照留在既有單元件／除錯入口處理，不冒充整盤專案。未知舊修訂或未知新 schemaVersion 不猜測轉換。原始上傳檔案不覆寫；新匯出只使用新格式。

## 7. 程式責任與相依範圍

以下為建議責任邊界，不是已新增的檔案清單。

| 責任 | 調整 |
|---|---|
| 專案契約／解析／序列化 | 與 Three.js 解耦；統一白名單、預設值、引用驗證與舊快照轉換。 |
| 元件與組裝庫 | 保留現有幾何／電性，增加相容版本、安裝及參數／狀態契約。 |
| 預設專案 | 將 BOARD 024 清單搬為資料；啟動與匯入共用建立流程。 |
| 場景建構 | 接受 configuration；結構、附掛姿態、固定導電片與視角取自資料／內建規格。 |
| 路由上下文 | 取自當前專案；移除固定線槽索引、過門 ID 與盤面尺寸假設。 |
| 電性建構 | 從配置產生來源、負載、附掛連動及固定接線，取消全域固定設備清單。 |
| 專案 session／UI | 擁有當前 runtime、工作代號與資源生命週期；替換後所有事件使用新 session。 |

保留 TypeScript strict、模型基準及既有教學電性。單元件檢視不得再依賴全域唯一 MC1；以被檢視實例與其有效組裝建立獨立檢視。
