# A04 匯入路徑修正

## 原因

先前人工產生的 A04 snapshot 將 26 條實體線全部標記為 `viaDucts: []`，並直接保存高架、盤外的 `points`。例如 QF1:T1 → MC1:1L1 的 W01 高達 Y=182，繞到 Z=-122；原生手動路由則經過第 2 條線槽（索引 1），最高 Y=93。這些是場景比例座標，不是毫米。

實際重現確認：`importBoardSnapshot()` 接受舊檔後，其路徑座標與舊檔完全相同，並非匯入時的世界／局部座標轉換錯誤。`prepareWireRestore()` 只檢查端子、碰撞及操作板側範圍，不替保存的路徑重新選線槽。普通匯入保留精確路徑的行為不應修改。

## 修正

加入明確的離線重新走線工具，完整匯入驗證後移除暫存模型上的舊線，再逐條呼叫與手動接線相同的 `WiringController.connect()`。保留元件規格、端子、電氣接線端點與 wire ID；由 `createBoardSnapshot()` 匯出，並由另一個全新模型實際匯入驗證。路由失敗即報錯，不產生假線，也不放寬碰撞檢查。

```sh
npm ci
npm run reroute -- input.json output.json
# 同時驗證關閉操作板，輸出可直接操作按鈕的盤面：
npm run reroute -- input.json output.json --close-panel
```

工具不覆寫原檔或既有輸出；輸出保持未送電。這不是新的網站匯入格式，也不會改動現有 Site。應用程式／模型／一般匯入仍為 WIRE-R12，無須為此次 JSON 修正重新部署網站。

## 驗證

- 舊檔回歸：實際匯入保留原路徑，但 W01 與原生路由的比對失敗；重算後通過。
- 完整 A04：26 條實體線、8 條外接線、3 條固定組裝線；22 個元件的 definition／placement／terminals 與使用者 R12 空盤快照逐項一致。
- 26 條線由原生路由生成，保留全部 ID 與端點；盤內 16 條線依路由器選線槽，操作板側 10 條線維持側邊直連。
- 閉合狀態匯入、兩輪展開／收合、再次匯出／匯入均通過實際 Three.js 幾何檢查；最小線間距約 4 場景單位，未降低原有 3.5 間距限制。
- 通電待機、啟動、自保持、停止、再次啟動、TH TEST 警報、TH RESET 不自啟、控制電源中斷／恢復不自啟，11 個狀態檢查通過。
- `npm test`：108 項通過、0 失敗，包含 3 項新增的原生重新走線回歸。

以上為實際 Node／Three.js 路由、匯入與電性引擎測試，不是只驗 JSON 語法；不代表瀏覽器目視驗收。此次本機 Chromium 在載入預覽時受管理政策阻擋（ERR_BLOCKED_BY_ADMINISTRATOR），未完成瀏覽器端驗收。

控制電源與三相主電源仍沿用現有的獨立教學模型；本次只修正幾何路徑，沒有變更電路連接或實體設備額定值。
