# WIRE-R18 操作板背面走線驗收

## 問題與根因

R17 已能將使用者的操作板收合，但使用者的收合畫面仍有繞到外框、跨過燈與按鈕正面的長矩形路徑。以既有 11 線專案和課堂 22 線專案能重現同類行為；這次截圖沒有附新的接線 JSON，因此不能將截圖中每一條線都對應到確定的 wire ID。

舊操作板側直連沿用世界 Y 抬高和後側出口，再接受第一個通過碰撞的橋接路徑。操作板側的限制只有過門端子台半平面，缺少板背範圍與正面禁區；路徑即使沒有碰到 mesh，仍可跑到操作面上方。姿態快取也只按舊幾何規則驗證，會繼續接受這種路徑。這不是電性接錯，也不是把線隱藏即可解決的渲染問題。

## 最終行為

- 依操作板規格、端子高度和當前矩陣建立局部板背範圍。兩端都在板上的接線限制於板背，連到過門端子台的接線另使用通往指定側的走線區域。
- 所有涉及操作板的路徑禁止穿越操作正面；同板直連不借道端子台區域。驗證整條線段在區域聯集中的連續覆蓋，不能只看兩端點。
- 優先比較直角短路徑與板背橫向路徑，以路徑長度及轉折成本選擇候選。受阻時使用有限網格的 weighted A*；這是有界近似搜尋，不保證全域最短。
- 網格保留精確端子座標，不將局部邊界點四捨五入。變體 0 保留第一條成功解，後續變體比較其他候選，避免重試又取得同一條路。
- 新路徑、開闔快取與舊幾何還原使用相同區域限制。正常專案只保存端點，匯入時重新走線；歷史診斷快照要求原路徑合法，不會靜默修復其幾何。
- R17 完整線組規劃、雙工作姿態預驗證與失敗還原保留。元件幾何、端子、電性和原有實體／線距／自交檢查未變。

## 可重現的路徑比較

數值是 scene-units，並非實物毫米。下列是指定案例的閉合姿態結果，不能推論任意線組都會有相同比例改善。

| 案例 | R17 路徑長度 | R18 路徑長度 | R18 結果 |
|---|---:|---:|---|
| 使用者 11 線中的 W07，PB5:1 → TB1:45B | 525.62 | 343.206 | 5 個路徑點，最高 Y = 31.325，低於板片下表面 Y = 50.75 |
| 單獨 HL3:2 → PB5:4 | 366.35 | 186.82 | 3 個路徑點，固定 Y = 11.825，同板背面連接 |

R17 的 W07 實際路徑保存在 `qa/fixtures/r17-front-excursion.route.json`。回歸先證明這條路徑仍符合端子、實體及自交檢查，再把它注入閉合快取；R18 必須重新求解，不能因快取命中而直接接受。

## 驗證範圍

`qa/panel-backside-check.mjs` 使用獨立的板片局部幾何 oracle，涵蓋 11 線反覆開闔、錯誤快取、同板短路徑雙向連接、平移升高／90°與180°盤面、A／B 過門側和完整線段區域覆蓋。

`qa/panel-planner-check.mjs` 的 11／22／23 線原序、反序、交錯順序共 168 個 prefix，全部加入板背／正面檢查；另外驗證反覆開闔、刪線重接、閉合專案匯出匯入、實體障礙與交易失敗還原。

`qa/panel-grid-check.mjs`、`qa/panel-grid-variants-check.mjs` 和 `qa/panel-candidate-variants-check.mjs` 驗證小數 anchor、板背邊界、矩陣變換、不同替代路徑、障礙物、預算／耗盡診斷及取消。搜尋核心的 37° 測試屬數值健全性檢查；正常專案格式仍只接受 90° 的整數倍旋轉。

本次驗證展開與收合兩個靜態工作姿態，未建立柔性線材長度、鉸鏈彎曲或翻轉掃掠物理。使用者已免除瀏覽器／WebGL 視覺測試；Node 幾何驗證不聲稱取代實際畫面驗收。

## 執行結果（2026-09-15）

- 修正前：板背／短路徑回歸於 R17 失敗；網格及分階段候選的變體測試於初版實作失敗（各只有 3 條不同候選）。修正後皆通過。
- `npm test`：213 項通過、0 失敗、0 跳過，包含 strict TypeScript、原有模型幾何基準、電性、走線與上述新增回歸。
- 168 個逐步接線狀態的雙姿態矩陣、實體障礙失敗還原、快取重新驗證及匯入匯出測試通過。
- 獨立審查另驗證相鄰／遠距 gateway B↔B，以及操作板→MC1、操作板→TB1 A 側的混合路由，均可開闔並通過實體及操作正面檢查。
- `npm run build`（含 standalone 匯出）成功；離線 HTML 的內嵌 JavaScript 語法及逐位元組一致性檢查通過。
